## Replit Prompt — Replace Random “Most Polarised” With a Real Controversy + Polarisation Topic Model (LUM News)

In this existing **LUM News** project, replace the placeholder **random polarisation score** with a **meaningful, explainable polarisation algorithm** that better selects truly controversial topics and ranks “Most Polarised” stories accordingly.

The current system:

* Polarisation score = random 0–99 (placeholder)
* Topic categorization = simple keyword matches
* “Most Polarised” = sort by random score

This must be upgraded so “Most Polarised” reliably surfaces **high-controversy, high-framing-difference stories** (politics, war, social issues, elections, geopolitical conflicts), not random noise.

---

# 1) New requirements: what “Most Polarised” should mean

Define polarisation as a **composite score** that reflects:

1. **Controversial topic likelihood**

   * Some topics are inherently more polarising than others (e.g., elections vs weather).
2. **Loaded / conflict language (“controversy signals”)**

   * Language like “outrage,” “backlash,” “slams,” “scandal,” “accused,” “propaganda,” “illegal,” etc.
3. **Framing divergence across sources (story-level)**

   * Different sources using very different headlines / tones for the same event.
4. **Sentiment spread (story-level)**

   * High variance in sentiment across articles covering the same story is a polarisation signal.
5. **Source diversity**

   * A story covered by many sources and regions has more room for conflicting narratives.
6. **Engagement bait / sensationalism signals** (optional)

   * Excessive caps, exclamation points, “you won’t believe,” etc. should boost “controversy” slightly but not dominate.

---

# 2) Replace random scoring with an explainable scoring pipeline

Implement a deterministic scoring system that assigns:

* **Article Polarisation Score (0–100)**
* **Story Polarisation Score (0–100)** aggregated from its articles
* **“Reasons”** (explainability) stored with each article/story so UI can show “Why this is polarised”.

Example reasons:

* “Topic weight: US Politics (+20)”
* “Controversy keywords detected: scandal, backlash (+12)”
* “High sentiment variance across sources (+15)”
* “Framing divergence high: headline similarity low (+18)”
* “Covered by 10 sources (+10)”

Convert this into score contribution:

* `topicScore = topicWeight * 30` (max 30 points)

Enhance categorization with:

3. **Policy-vs-neutral detection**

   * “climate policy” vs “climate discovery”
4. **Multi-topic output**

   * Allow more than 1–2 topics if confidence is high. Store topic confidence.

Store:

* `topics: [{ name, confidence }]`

# 5) Story-level polarisation: framing divergence + sentiment variance

This is where “Most Polarised” becomes real.

## 5.1 Framing divergence (headline similarity)

For articles in the same story cluster:

* Compute pairwise similarity between headlines using one of:

  * Simple Jaccard similarity on tokens, or
  * Cosine similarity via TF-IDF (still doable locally), or
  * Embedding similarity (if embeddings exist in your project)

Then define:

* `framingDivergence = 1 - averageSimilarity`

Convert to points:

* `framingScore = clamp(framingDivergence * 25, 0, 25)`

Interpretation:

* Similar headlines = low divergence (less polarised)
* Very different headlines for same event = high divergence (more polarised)

## 5.2 Sentiment variance across sources

If you already compute sentiment per article, then per story:

* Compute variance / spread of sentiment scores across articles.
* High variance = higher polarisation.

Convert to points:

* `sentimentScore = clamp(sentimentVariance * scaleFactor, 0, 15)`

If sentiment is missing, approximate with:

* Positive/negative word lists (lightweight fallback)

---

# 6) Source diversity score (story-level)

For a story cluster:

* count distinct sources
* count distinct countries/regions (if metadata exists)

Convert to points:

* `diversityScore = clamp(log2(1 + sourcesCount) * 4, 0, 15)`
* optionally add region diversity bonus (max 5)

This pushes up stories with:

* multiple outlets covering the event
* multiple regions framing it differently

# 7) Final scoring formula (0–100)

Compute **ArticleScore** first:

**Article Polarisation Score**

* `topicScore` (0–30)
* `controversyScore` (0–25)
* `sensationalismScore` (0–5)
* `baseNoise` (0–3 small deterministic hash so ties don’t look identical)

Then compute **StoryScore**:

**Story Polarisation Score**

* average(articleScore) (0–60)
* * `framingScore` (0–25)
* * `sentimentScore` (0–15)
* * `diversityScore` (0–15)

Cap at 100.

Store:

* `story.polarisationScore`
* `story.polarisationReasons[]`
