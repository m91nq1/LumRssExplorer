Use React hooks (useState, useEffect) to manage form state and loading states.

On submit:

For Login: send POST to /api/auth/login with { email, password }.

For Signup: send POST to /api/auth/register with { name, email, password }.

Show a small, subtle error toast or message if backend returns an error.

Show a loading spinner/indicator on buttons while the request is in progress.

Create a small authApi.ts helper module in the frontend, something like:

4. Backend: email/password + Google stubs

In the Node + Express backend, add an auth router (if not already present) with:

Endpoints

POST /api/auth/register

Validate email & password.

Hash the password (use bcrypt or argon2).

Create user in a simple in-memory store or existing DB (e.g. users table).

Return a JWT or session cookie (choose one pattern and stick to it).

POST /api/auth/login

Validate credentials.

If correct, return JWT or set session cookie.

If wrong, return 401 with error message.

GET /api/auth/me

Check auth (JWT in header or session cookie).

Return current user info (id, email, name, maybe plan).

Google OAuth endpoints (basic skeleton):

GET /api/auth/google

Starts the Google OAuth flow (redirect to Google).

GET /api/auth/google/callback

Handles Google callback.

Reads Google profile (email, name).

Creates or finds a user in DB.

Issues JWT / session cookie.

Redirects back to the frontend (e.g. / or /dashboard).

You can use a simple library like passport + passport-google-oauth20 OR hand-roll with the official Google OAuth client. For now, it’s okay to:

Implement a partial Google flow (with TODOs), but:

Set up the route structure and functions clearly so I can drop in real credentials later.

Make sure Google client ID/secret are read from env vars:

GOOGLE_CLIENT_ID

GOOGLE_CLIENT_SECRET

GOOGLE_REDIRECT_URI

Never hard-code them.
